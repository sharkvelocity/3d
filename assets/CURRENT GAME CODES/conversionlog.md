# Babylon.js to Three.js Conversion Log

This document tracks the progress of migrating the game's 3D rendering engine from Babylon.js to Three.js. Its purpose is to provide a clear overview of what features have been successfully ported and what work remains to achieve feature parity.

---

## ✅ Completed Features

The following core systems have been successfully implemented in the Three.js engine:

### 1. Core Rendering & Physics
- **Engine Setup:** Initialization of the `THREE.WebGLRenderer`, `THREE.Scene`, and `THREE.PerspectiveCamera`.
- **Physics World:** Integration with `Cannon.js` to create a functional physics simulation with gravity.
- **Render Loop:** A stable `requestAnimationFrame` loop is in place, driven by a `THREE.Clock` for frame-rate independent updates.

### 2. Player Controller
- **First-Person Controls:** Full implementation of `PointerLockControls` for standard mouse-look.
- **Physics-Based Movement:** Player movement (WASD, Sprint, Crouch, Jump) is driven by applying forces to a `CANNON.Body`, providing realistic motion, collision, and gravity.
- **Camera Synchronization:** The visual camera's position is correctly synced to the player's physics body each frame.

### 3. World & Environment
- **Procedural House Generation:** The `HouseBuilder` service has been fully ported. It correctly generates the entire mansion layout, including floors, multi-material walls, roofing, and all fixtures (lights, switches, breaker box) as `THREE.Mesh` objects.
- **Static World Collision:** All generated house geometry is paired with static, immovable `CANNON.Body` instances, creating a solid, collidable game world.
- **Atmospheric Lighting:** The scene's lighting has been overhauled to be significantly darker, creating a suspenseful horror atmosphere.
- **Functional Lights:** In-game lights are functional and can be toggled based on the game state.
- **Weather & Atmosphere:**
    - Scene fog is implemented and changes based on weather conditions.
    - Animated particle systems for rain and snow are now functional.

### 4. Player Interaction & Items
- **Input Hooks:** The `useThreePlayerInput` hook has been completely ported, handling all keyboard and mouse events for gameplay actions.
- **Raycast Interaction:** Item pickup is functional using `THREE.Raycaster` to detect interactable objects.
- **Dynamic Item Spawning:** The system correctly listens to the `placedItems` array in the Zustand store and dynamically loads/renders GLTF models for items placed in the world.
- **Item Physics:** Each spawned item is given a `CANNON.Body`, making them physical objects that can be moved or bumped into.
- **Item Placement System:** The "placement ghost" feature is implemented. Holding right-click correctly shows a transparent preview model for precise item placement. Dropping items (`G` key) is also functional.
- **Inventory Management:** Switching items with number keys (`1-4`) and the mouse wheel is fully implemented.
- **Active Item Functionality:**
    - **Held Item Viewmodels:** The system now loads and displays the 3D model for the player's currently equipped item.
    - **Flashlight:** The flashlight is fully functional, casting a `THREE.SpotLight`.
    - **UV Light:** Fully functional with a dedicated light that illuminates a separate "UV" render layer.
    - **EMF Reader:** The viewmodel's LEDs now light up correctly based on the game state's `emfLevel`.
    - **Lighter:** The lighter now has a functional point light and a realistic multi-flick ignition sequence with sound.
    - **Spirit Box & Smudge Sticks:** The audio and timer logic for these items is now active.

### 5. Ghost & Core Gameplay Logic
- **`useGameLogic` Integration:** The core background timers for sanity, temperature, and AI decision-making are running.
- **Ghost Entity & Pathfinding:**
    - The ghost's 3D model, physics body, and initial spawning are implemented.
    - The ghost now correctly follows multi-point paths generated by the `useGameLogic` AI hook.
    - Implemented "arrival detection" to progress through waypoints.
    - The ghost is now aware of which room it currently occupies and updates the game state accordingly.
- **Ghost Hunt AI & Abilities:**
    - Implemented hunt state detection (`isHunting`).
    - Implemented line-of-sight (LoS) detection via raycasting.
    - Implemented chasing behavior (targeting player on LoS, and last known position on LoS loss).
    - Integrated dynamic ghost speed from `useGameLogic` into the physics body's velocity.
    - Implemented player death check based on proximity during a hunt.
    - Implemented visual changes for hunting state (opacity and flickering).
    - **Ghost Animation:** The ghost is no longer in a T-pose and now plays idle, walking, or running animations based on its AI state.

### 6. Audio System
- **Sound Manager:** A full `SoundManager` has been implemented for the Three.js engine.
- **Audio Playback:** The system now loads and plays all game audio, including weather-specific ambient loops, indoor/outdoor footsteps, and cached item sound effects.
- **Positional & Global Audio:** Both `THREE.PositionalAudio` and global `THREE.Audio` are supported and used where appropriate.

### 7. Evidence Systems (Partial)
- **Freezing Breath:** A particle system attached to the camera now correctly displays puffs of cold breath in low temperatures.
- **Ghost Orb:** A visual placeholder for the Ghost Orb is implemented and correctly placed on a separate render layer.
