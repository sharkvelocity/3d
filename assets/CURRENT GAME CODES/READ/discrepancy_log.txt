## [REF: D-013] - Loading Stall Due to Babylon.js Dependency Conflict

**File(s) Involved:**
- `services/HouseBuilder.ts`
- `index.html`

**Date Reported:** 2024-08-11

**Description:**
The application's loading screen would appear but never progress. The root cause was a conflict in how the Babylon.js library was being accessed. The `index.html` file loads Babylon.js via a global `<script>` tag, which creates a `window.BABYLON` object. However, the `HouseBuilder.ts` service was attempting to load Babylon.js modules using ES `import` statements (e.g., `import { Scene } from '@babylonjs/core'`). This created a conflict where the imported modules were not resolving correctly, causing the `buildHouse` function to fail silently and stalling the entire loading process.

**Status:** Resolved

**Resolution:**
The `HouseBuilder.ts` file was refactored to align with the global script loading strategy defined in `index.html`. All ES module imports from `@babylonjs/core` were removed. All references to Babylon.js classes, types, and functions (e.g., `Scene`, `Vector3`, `MeshBuilder`) were updated to use the global `BABYLON` object (e.g., `BABYLON.Scene`, `BABYLON.Vector3`, `BABYLON.MeshBuilder`). This ensures the entire application consistently uses the single, globally-loaded instance of the Babylon.js engine, resolving the loading stall.
**Date Resolved:** 2024-08-11

## [REF: D-012] - UI Redesign of Loadout and Loading Screens

**File(s) Involved:**
- `store.ts`
- `components/LoadingScreen.tsx`
- `components/MainMenu.tsx`
- `index.css`

**Date Reported:** 2024-08-10

**Description:**
The user requested a significant redesign of two UI screens.
1.  **Loading Screen:** The standard progress bar was replaced with a dynamic "chase" sequence. A randomly selected ghost icon now moves across the screen towards a randomly selected, wobbling player icon as loading progresses. This required adding state to Zustand for the icon URLs and creating custom CSS animations.
2.  **Loadout Screen:** The previous icon-based grid was replaced with a text-based, two-column layout. The left column lists available items, and hovering over an item reveals a tooltip with its description. The right column serves as the "manifest," showing the three selected item slots. This change was implemented to provide a cleaner, more organized view without relying on icons.

**A note was also made to avoid any future modifications to `index.html` as it has been a source of recurring issues when changed.**

**Status:** Resolved

**Resolution:**
The `LoadingScreen.tsx` component was updated to render the new animated icon chase bar. The `LoadoutScreen` component within `MainMenu.tsx` was rewritten to use the new list-based layout with CSS tooltips. The Zustand store (`store.ts`) was updated to support the random icon selection for the loading screen. New CSS keyframe animations were added to `index.css`.
**Date Resolved:** 2024-08-10

## [REF: D-011] - Build Configuration Conflict in `index.html`

**File(s) Involved:**
- `index.html`
- `package.json`

**Date Reported:** 2024-08-09

**Description:**
The application's `index.html` contained legacy CDN script includes and a `<script type="importmap">` block, which directly conflicted with the project's Vite-based build setup. This caused unreliable module loading and prevented dependencies from being managed correctly through `package.json`.

**Status:** Resolved

**Resolution:**
The `index.html` file was cleaned to remove all CDN script tags and the `importmap`. The application now relies solely on Vite to bundle and manage all dependencies. The `package.json` file was updated to explicitly include `react`, `react-dom`, `@babylonjs/core`, `@babylonjs/loaders`, `cannon`, and `@types/cannon` to ensure a stable and correct build.
**Date Resolved:** 2024-08-09

## [REF: D-001] - Performance Bottleneck in Procedural House Generation

**File(s) Involved:**
- `services/HouseBuilder.ts`

**Date Reported:** 2024-07-29

**Description:**
The initial implementation of procedural house generation in `buildHouse` used Constructive Solid Geometry (CSG) operations. This approach was computationally expensive, causing a noticeable delay during the "Raising walls..." step of the loading screen.

**Status:** Resolved

**Resolution:**
The `HouseBuilder.ts` service was refactored to use a more performant method of merging simple box meshes instead of CSG. This significantly improved loading times. The current implementation in Three.js continues this performant approach.
**Date Resolved:** 2024-07-29
