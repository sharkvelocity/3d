**LIFECYCLE BLINDNESS (2025-11-30)**
- **Failure:** I assumed that because I wrote `clearGameAssets`, the game would automatically work upon reloading. I forgot that disposing of a Manager (`ItemManager`) requires explicitly creating a *new* instance of it during the load sequence.
- **Consequence:** The game loaded visually, but had "Zero Function." No items worked. It was a zombie state.
- **Lesson:** Initialization is a loop. If you tear it down (`dispose`), you MUST verify the rebuild logic (`new Class()`) exists in the loader. Never assume persistence of logic objects across scene clears.

**HITBOX PLACEMENT (2025-11-30)**
- **Failure:** I tried to parent a hitbox to a complex, scaled GLB model (`front_door`), causing the hitbox to be lost in transformation space.
- **Correction:** Decouple interaction logic from visual model logic. I placed the hitbox directly in the scene root at the map's layout coordinates. This is the "Source of Truth" for where the door *should* be.

**PHYSICS TRAPS (2025-11-30)**
- **Failure:** I allowed a complex, concave GLB (`front_door`) to generate a Mesh Impostor physics body. The physics engine couldn't handle the shape correctly, trapping the player inside ("sucked in").
- **Correction:** Simplify collision. For complex static props, rely on `checkCollisions` (Ellipsoid sliding) instead of full rigid body physics (`PhysicsImpostor`), unless interactions like bouncing objects are critical.

**HITBOX MATH (2025-11-30)**
- **Failure:** I added a Parent's World Position to a Child's Local Position slot. This launched hitboxes into orbit.
- **Correction:** Always transform World coordinates into the Parent's Local Space using the inverse world matrix before assigning to a child.
- **Lesson:** Parenting changes the coordinate system. `position` becomes local.

**CLIPPING & SCALING (2025-11-30)**
- **Observation:** If a player hugs a wall and sees through it, the Camera Near Clip (`minZ`) is too large relative to the collider size.
- **Fix:** Lower `minZ` (e.g., 0.1) to ensure the rendering starts closer than the physical collider stops.

**DIRECTIONALITY & SPATIAL AWARENESS (2025-11-30)**
- **Critical Lesson:** I have struggled with relative directions (Left vs Right). I must refer to the provided visual guide.
- **The Rule:**
    - **X- (Negative X) is LEFT** (Blue Box/Left Side of Screen).
    - **X+ (Positive X) is RIGHT** (Red Box/Right Side of Screen).
    - **Y- (Negative Y) is DOWN**.
    - **Y+ (Positive Y) is UP**.
    - **Z- (Negative Z) is CLOSER** (Towards Camera/Out of Page).
    - **Z+ (Positive Z) is FARTHER** (Away from Camera/Into Page).
- **Visual Aid (Implemented 2025-11-30):** In Dev Mode, interactive hitboxes (Doors, etc.) now display a **Blue-to-Red gradient** texture.
    - **BLUE Side = LEFT (-X)**
    - **RED Side = RIGHT (+X)**
    - Look at this visual when debugging placement/orientation.

**LIGHTER TUNING & LAYER MASKS (2025-11-30)**
- **Problem:** The user reported the lighter flame separating from the body when moved.
- **Diagnosis:** The lighter model is rendered on the `VIEWMODEL_LAYER` (always on top), but the particle system was on the default layer. This caused depth sorting issues where the gun would draw *over* the fire, making it look behind or separated.
- **Fix:** Assigned `VIEWMODEL_LAYER_MASK` to the `flameSystem` so it renders in the same camera pass as the gun. Also simplified emitter parenting.
- **Lesson:** When dealing with ViewModels (FPS hands), ALL associated effects (particles, lights) must usually share the same LayerMask to ensure consistent depth sorting and visibility.

**THE FRONT DOOR ANIMATION REGRESSION (2025-11-30)**
- **Event:** I tried to "fix" the front door animation by implementing manual pivots to solve a rotation issue ("helicoptering"). This broke the door completely, leaving it stuck open.
- **Cause:** Over-engineering. The GLB file *already* contained working animations (`leftAction`, `rightAction`). By ignoring them and trying to animate pivots manually, I introduced bugs with initial state and rotation logic.
- **Lesson:** **Respect the Asset.** If an asset has baked animations, USE THEM. Do not try to re-invent the wheel with code-based transformations unless absolutely necessary.
- **Correction:** Reverted to using the baked `AnimationGroup` logic, ensuring they are cloned properly for the instance and reset to frame 0 (Closed) on spawn.
